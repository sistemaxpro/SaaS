🔐 Integración de Timeout de Sesión

Guía de implementación del sistema de cierre de sesión automático después de 20 minutos de inactividad

📋 Introducción

El sistema de timeout de sesión cierra automáticamente la sesión del usuario después de 20 minutos sin actividad, mejorando la seguridad de la aplicación.

ℹ️ Información: El sistema incluye validación tanto en servidor como en cliente, con advertencias visuales para el usuario.

🚀 Instalación Rápida

Paso 1: Ya está instalado

El middleware de timeout se carga automáticamente en config/bootstrap.php

No requiere instalación adicional en el servidor.

Paso 2: Agregar script en tus páginas

En cualquier página donde quieras mostrar la advertencia de timeout:

<!-- Agregar antes de </body> -->
<script src="/public/assets/js/session-timeout-warning.js"></script>

Paso 3: Verificar que funciona

Abre el navegador (F12) → Console y busca el mensaje:

[Session Timeout Warning] Sistema de advertencia de timeout iniciado

📝 Ejemplo de Integración en Layout Base

Si tienes un layout o template base que se usa en todas las páginas:

<?php
require_once __DIR__ . '/../config/bootstrap.php';
Session::requireLogin();
?>
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>Mi Aplicación</title>
</head>
<body data-session-active="true">

    <!-- Contenido de tu página -->

    <!-- Script de timeout SOLO si la sesión está activa -->
    <?php if (Session::isLoggedIn()): ?>
        <script src="/public/assets/js/session-timeout-warning.js"></script>
    <?php endif; ?>

</body>
</html>

⚙️ Configuración

Cambiar tiempo de timeout

En PHP: Editar config/session-timeout-middleware.php

define('SESSION_TIMEOUT_MINUTES', 20);  // Cambiar a otro valor

En JavaScript: Editar public/assets/js/session-timeout-warning.js

const CONFIG = {
    timeoutMinutes: 20,        // Timeout total
    warningTimeMinutes: 2,     // Mostrar advertencia a los 18 minutos
    checkIntervalSeconds: 10,  // Verificar cada 10 segundos
};
⚠️ Nota: Cambiar timeout a menos de 5 minutos puede causar problemas con operaciones lentas.

🔄 Flujo de Funcionamiento

Evento Lo que sucede Tiempo
Usuario inicia sesión Se registra el tiempo de actividad 0 min
Usuario hace clic, escribe, etc. Se actualiza el tiempo de actividad Continuamente
Usuario se va, sin actividad Contador de inactividad comienza -
Faltan 2 minutos para timeout Se muestra modal de advertencia 18 min
Usuario hace clic en "Continuar" Sesión se extiende 20 minutos más 18 min
Usuario no responde Sesión se cierra, redirige a login 20 min

💾 Métodos PHP Disponibles

Método Descripción Retorna
Session::checkInactivity($min) Verifica y valida inactividad bool
Session::updateActivityTime() Actualiza tiempo de actividad manual void
Session::getTimeRemainingBeforeTimeout() Obtiene segundos restantes int|null

Ejemplo: Operación Larga

<?php
// Procesamiento largo
while ($procesando) {
    // ... hacer algo ...

    // Cada 5 minutos, actualizar actividad
    if ($iteraciones % 50 == 0) {
        Session::updateActivityTime();
    }
}
?>

❓ Preguntas Frecuentes

¿Qué pasa si el navegador se cierra?

La sesión se destruye automáticamente (comportamiento por defecto de PHP).

¿El usuario es forzado a cerrar sesión?

No, recibe una advertencia a los 18 minutos. Puede extender la sesión haciendo clic en "Continuar sesión".

¿Se puede desactivar el timeout?

Sí, cambiando SESSION_TIMEOUT_MINUTES a un valor muy alto (ej: 99999).

¿Funciona sin JavaScript?

Sí, el servidor valida en cada request. Sin JS no hay advertencia visual, pero la sesión se cierra igual.

¿Afecta a APIs/Tokens JWT?

No, solo afecta a sesiones PHP. Los tokens JWT tienen su propio sistema de expiración.
